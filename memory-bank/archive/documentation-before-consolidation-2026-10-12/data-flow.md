# Потоки даних — MVP 1
Погоджений життєвий цикл: заявка → утримання 30 хв → рішення адміністратора → підтверджений запис або звільнення. Поза робочим часом заявка без гарантії слоту. Google Sheets — бізнес-реєстр; Calendar синхронізується через backend. Правила: [налаштування салону](drafts/salon-settings.md).
Базові [потоки та логічна модель](drafts/Data-Flow.md) збережені.

## AI-виклик за погодженою стратегією
Збірка контексту й обмеження описані в [Context Strategy](drafts/context-strategy/README.md). До виклику прибрати дублікати, відібрати актуальні джерела та потрібну історію; за необхідності стиснути без втрати точних полів, згоди й заперечень. Після зміни матеріалів анулювати відповідні кеші.
1. Визначити операцію й перевірити, чи достатньо коду.
2. Перевірити ліміти сценарію, користувача й проєкту; зарезервувати бюджет.
3. Вибрати модель за [Model Strategy](model-strategy.md), відібрати актуальні матеріали й мінімальну історію без embeddings.
4. Виконати виклик із лімітами output/reasoning та потрібною JSON Schema.
5. Перевірити формат, допустимі ID, факти й бізнес-правила; AI не підтверджує резервування.
6. Записати usage і результат, звірити резерв із фактичною вартістю. Відсутній usage позначити для звірки, не вважати витрати нульовими.
7. За дозволеної помилки й залишку бюджету — retry/fallback у встановлених межах; інакше уточнення, код або адміністратор.
8. Виконувати бізнес-дію через backend; після тайм-ауту перевіряти її фактичний результат до повтору.

Облік на кожну спробу: IDs, модель/endpoint, токени, вартість, latency, причини повторів, помилки й limit events. Не включати зайві контакти та повні діалоги в журнал витрат.
