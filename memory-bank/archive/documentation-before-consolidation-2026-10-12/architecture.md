# Архітектура — MVP 1
Актуальні погоджені уточнення: [Стиль салон](drafts/salon-settings.md). Telegram → TypeScript/Node.js backend → Google Sheets (бізнес-реєстр) і Google Calendar (відображення); n8n для сценаріїв; PostgreSQL для технічного стану/блокувань/бюджету. Docker Compose локально на комп’ютері власника. Попередня пропозиція VPS замінена.
Базова [архітектурна чернетка](drafts/Architecture.md) збережена. Погоджені рішення щодо моделей: [Model Strategy](model-strategy.md).

## Доповнення від 2026-10-12
Погоджено [Context Strategy](drafts/context-strategy/README.md): структурований стан окремо від історії, вибіркові джерела, версійовані промпти й кеші, бюджет запиту та спільний облік retries між backend/n8n/SDK.
Модель обирається за типом операції; до виклику перевіряються бюджети. Backend контролює доступ, схему й зміст результату, допустимі дії та облік витрат. n8n організовує сценарії й фонові дії.
Для паралельних AI-запитів потрібне резервування бюджету й звірка usage. Конкретна реалізація ще не обрана.
MVP без embeddings і векторної бази: структурований каталог, затверджений FAQ, текстовий пошук і синоніми.
Вичерпання AI-бюджету не зупиняє детерміновані функції запису й повідомлень. Опційні AI-функції не розширюють MVP автоматично.
