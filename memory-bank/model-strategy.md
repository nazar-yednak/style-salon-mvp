# Model Strategy — Стиль салон, MVP 1

Погоджені рішення, актуалізовано 2026-10-12. Реалізацію й тестування ще не виконано. Основне джерело моделей, вартості й лімітів; контекстні правила — [Context Strategy](context-memory-strategy.md). Попередні версії збережено в [архіві](archive/README.md).

## AI Operations
Консультація за базою знань і підбір послуг використовують AI. Розпізнавання наміру, витягування полів, нестандартні уточнення, класифікація передачі й підсумки використовують AI лише там, де недостатньо кнопок, форм і шаблонів.
Адмін-команди природною мовою відкладено після MVP. Автоматичну AI-діагностику виключено; ручний аналіз за потреби в бюджеті. AI-пояснення статистики лишається опційним, розрахунки — кодом.
Код виконує авторизацію, валідацію, доступність, резервування, перенесення, скасування, синхронізацію, статистичні розрахунки та службові повідомлення.

## Model Requirements
Українська мова; короткі класифікація/поля — без reasoning з JSON Schema; консультації — за джерелами; складний підбір — умовне reasoning; summary зберігає факти й заперечення. Tools лише за потреби й через backend. Зображення не потрібні.
Input-бюджети операцій: короткі до 1000, типова консультація до 3000, складна до 5000, підсумок до 5000 із результатом до 300 токенів. Точний розподіл і всі параметри — [Context Strategy](context-memory-strategy.md). Це практичні ліміти, а не максимальний context window моделі.
Structured output не доводить істинність. Memory Bank не передається клієнтській моделі. Якість українською ще перевірити.

## Model Routing
Погоджені бюджети операцій, промпти, пам’ять, пошук, стискання, кешування, параметри API та повтори: [Context Strategy](context-memory-strategy.md). Загальні ліміти цього документа мають пріоритет над максимумами окремої операції.
Спочатку перевірити можливість виконати операцію кодом. Потім визначити тип операції, бюджет і необхідний контекст.
Прості операції → H; складна консультація/підбір → M. B використовується лише після тестування. S — резерв складних задач і ручна технічна діагностика за потреби; G — її резерв.
Reasoning вимкнене у простих H/M-операціях; активується за складних порівнянь і суперечливих умов. У S/G обов’язкове: контролюємо effort і completion budget.
Tool calling — лише дозволені інструменти; виконання і права контролює backend. Немає самостійного підтвердження запису моделлю.
Для JSON Schema використовувати підтримуваний endpoint і вимогу підтримки параметрів. Джерела: [structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs), [tool calling](https://openrouter.ai/docs/guides/features/tool-calling).

## Embedding Strategy
MVP працює без embeddings і векторної бази. Каталог, FAQ, категорії, синоніми та текстовий пошук подають релевантні затверджені матеріали.
Sheets — бізнес-дані, PostgreSQL — пам’ять/технічні дані й індекс, Calendar — відображення. Деталі: [Data Flow](data-flow.md).
Ризики: пропуски перефразувань, застарілі джерела, зайві передачі людині, великий контекст. Без джерела — уточнення або адміністратор.
Перегляд рішення: суттєве зростання матеріалів або регулярні пропуски в українських тестах, які не усуваються простішим пошуком.

## Fallback Strategy
Не більше 1 retry на операцію та 2 на сценарій; не більше 1 переходу fallback на операцію та 2 на сценарій. Максимум 3 спроби на операцію, включно з первинною. Усі спроби входять у загальні ліміти.
Retry дозволений для тимчасових збоїв, rate limit, тайм-ауту чи відхиленої схеми за наявності бюджету. Fallback — недоступність основної моделі або відхилений результат після дозволеної спроби виправлення.
Відсутнє джерело, неоднозначність або бізнес-заборона → уточнення/людина, не повтори.
OpenRouter fallback реагує на помилки API; зміст перевіряє backend. [Документація](https://openrouter.ai/docs/guides/routing/model-fallbacks).
При тайм-ауті бізнес-дії спочатку звірити результат; retry AI не повинен дублювати бронювання.

## Cost Limits
Пілот тепер 300 користувачів; місячний hard limit залишається $10, soft $6. Усередині hard limit: $8 клієнтські операції, $2 адміністративні. Резерв завершення сценарію 20%. Погоджені уточнення мають пріоритет над попереднім позначенням пілоту на 100 користувачів.
| Ліміт | Типовий | Складний |
|---|---:|---:|
| Input, сумарно | 6000 | 24000 |
| Видимий output, сумарно | 1000 | 3000 |
| Reasoning, сумарно | 0 | 2000 |
| Загальний hard token limit | 7000 | 29000 |
| Усі AI-спроби | 5 | 12 |
| Грошовий soft limit | $0.004 | $0.030 |
| Грошовий hard limit | $0.006 | $0.050 |

Один користувач/місяць: soft $0.06, hard $0.10. Пілот 300 користувачів/місяць: soft $6, hard $10; адміністративний AI лише ручний/дозволений. Адмін керує змінами лімітів явною дією.
Максимум 2 reasoning-виклики на сценарій, включно з fallback. Типовий сценарій за потреби один раз стає складним; лічильники не скидаються.
На 80% токенів/викликів скоротити контекст. На грошовому soft limit вимкнути необов’язкові пояснення/reasoning, перейти до шаблонів і кнопок. Дешевша модель — лише дозволена й протестована.
Hard limit будь-якого рівня → припинити нові AI-виклики на цьому рівні, зберегти стан, продовжити кодом або через адміністратора. Записи й заплановані повідомлення продовжують працювати.
Перед викликом резервувати максимальну допустиму вартість з урахуванням паралельності; після usage звірити. Уже витрачені кошти не повертаються лімітом. Зміна ліміту — лише явним рішенням власника.

## Monitoring Strategy
На кожну спробу: timestamp, scenario/operation/request ID, тип сценарію, внутрішній user ID, запитана й фактична модель, provider/endpoint, версія тарифу, input/output/reasoning/cache tokens, фактична вартість або позначена оцінка, effort, номер спроби, retry/fallback причина, latency, помилка, результат і limit event.
Агрегати: total cost, cost per user, cost per scenario, model used, reasoning calls, retries, fallback events, latency p50/p95, errors. Облік без подвійного додавання reasoning.
Сповіщення власнику: $6/$10 місячного бюджету та прогноз перевищення. Менеджеру: передача через ліміт і користувацький hard limit. Технічному відповідальному: ланцюг помилок, вичерпані спроби, відсутній usage або неочікувана модель.
Щоденний підсумок: витрати, користувачі, ціна сценарію, reasoning, повтори, fallback і ліміти. Однакові сповіщення об’єднувати. Контакти й повні діалоги не потрібні для обліку.

## Assumptions
- Місяць — календарний; сценарій — одна консультація/дія до завершення, передачі або закриття.
- 300 користувачів × 4 сценарії — погоджений план; 75% типових/25% складних — неперевірене припущення.
- Типовий: 2 H по 800 input/120 output; 1 M по 2000/400, reasoning вимкнено.
- Складний: 4 H по 800/120; 3 M по 4000/600; підсумок H 5000/300; 2 M-reasoning по 500 токенів.
- Input включає промпт, правила, матеріали й фактично надіслану історію.
- Базова оцінка без retries/fallback, кешу, batch, платних інструментів та опційної діагностики.
- Чутливість: 10% додаткових оплачуваних повторів або 10% M-консультацій на S; S має той самий input/output і додаткові 500 reasoning.
- Токенні обсяги — припущення, не гарантія effort; якість моделей українською ще не виміряна.
- Податки, комісії, інфраструктура й доставки не включені. Ліміти — погоджена початкова політика, не прогноз рахунку.
