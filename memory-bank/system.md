# Правила Memory Bank — Стиль салон
Перед значущою роботою: AGENTS.md → цей файл → activeContext.md → потрібні документи з [карти](documentation-map.md).
Пам’ять розробки відокремлена від пам’яті клієнтського бота. Кореневі документи — актуальні; drafts/ — покажчики й джерела; archive/ — історія, не діючі правила.
Документація українською. Не вигадувати факти, доступи, матеріали, результати тестів чи особи. Погоджено ≠ реалізовано. Секрети поза Memory Bank.
Оновлювати при рішеннях, значущому прогресі, зміні плану/фокусу. Не логувати кожну репліку. Перед записом перечитувати файл, зберігати паралельні зміни; неоднозначність узгоджувати.
Один власник даних на тему; у пов’язаних файлах посилання. Закриті питання прибирати з актуального реєстру з записом у decisions.md; історію зберігати.
Постійне правило користувача: завжди перевіряти актуальність documentation-map.md і glossary.md при змінах проєкту чи документації та одразу оновлювати їх за потреби. Карта відображає структуру, компоненти й джерела; глосарій пояснює нові або змінені терміни. Без змістових змін не переписувати. За прямої заборони запису лише повідомити про потрібне оновлення.
Команди: VAN/INIT — старт; PLAN — план; THINK — вибір; DO/BUILD — виконання; LOG — запис; STATUS — стан; REFLECT — уроки; ARCHIVE — завершення.
tasks.md — єдиний реєстр задач; open-questions.md — незакриті рішення; decisions.md — підстави; progress.md — зроблене; research.md — джерела; inbox.md — необроблені нотатки.
Малі задачі ведуться тут, великі за потреби у projects/. Клієнтські промпти не містять Memory Bank.
Живі task controls й пам’ять Codex необов’язкові; не читати й не редагувати згенеровані файли пам’яті Codex. AGENTS.md, bootstrap і SVG збережені.
