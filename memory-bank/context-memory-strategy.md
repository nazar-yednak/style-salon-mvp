# Context and Memory Strategy

«Стиль салон», MVP 1. Погоджена архітектура; реалізація й тести ще не виконані. Оновлено 2026-10-12 відповідно до формату завдання. Зміст українською, заголовки — за вимогою. [Model Strategy](model-strategy.md).

## Context Sources
Системні правила, правила операції, JSON-схема/tools, поточне повідомлення, структурований стан, потрібні репліки/summary, затверджені матеріали Drive через індекс PostgreSQL, точні бізнес-дані Sheets і актуальні результати backend/Calendar.
Джерела завантажуються лише за потреби операції. Memory Bank, кошториси, SVG, секрети й чужі діалоги не передаються клієнтській моделі.

## Context Budget
Ліміти сценаріїв погоджені раніше; розподіл на операції погоджений як початкова політика для тестів.

| Рівень | Input | Видимий output | Reasoning | Усі AI-спроби |
|---|---:|---:|---:|---:|
| Типовий сценарій, сумарно | 6000 | 1000 | 0 | 5 |
| Складний сценарій, сумарно | 24000 | 3000 | 2000 | 12 |
| Коротка операція: намір, поля, передача | До 1000 | До 200 | 0 | У межах сценарію |
| Типова консультація | До 3000 | До 500 | 0 | У межах сценарію |
| Складна консультація або підбір | До 5000 | До 800 | До 1000 за умовою | У межах сценарію |
| Підсумок адміністратору | До 5000 | До 300 | 0 | У межах сценарію |

Залишок сценарію, грошовий бюджет і резерв для завершення мають пріоритет над максимумом операції. Кілька максимальних викликів можуть не поміститися в сценарій.
Перед спробою backend підраховує або консервативно оцінює весь запит, включно зі схемами tools; перевіряє токени, кошти й спроби; скорочує необов’язкове; резервує бюджет. Після відповіді звіряє usage.
На 80% ліміту скорочуємо контекст і переходимо до стандартного сценарію. Типовий сценарій один раз переходить у складний без скидання лічильників.
Резерв завершення 20%. Для типового запиту: правила 200, операція/схема 300, повідомлення 200, стан 300, історія 500, джерела 1500 = 3000 input. Це припущення розподілу, що перевіряється на реальних матеріалах.

## Prompt Architecture
| Блок | Зміст | Правило |
|---|---|---|
| Системні правила | Роль, українська, повноваження, захист даних | Короткі, стабільні, версійовані |
| Правила операції | Завдання, результати, уточнення й передача | Лише поточна операція |
| Схема результату / tools | JSON Schema й необхідні інструменти | Без зайвих схем |
| Структурований стан | Намір, поля, відсутні дані, ID й версія | Джерело — backend |
| Матеріали салону | Відібрані затверджені фрагменти | Джерело, версія, актуальність |
| Пам’ять діалогу | Підсумок і потрібні останні репліки | У межах бюджету |
| Поточний запит / tool results | Повідомлення й актуальні результати | Дані, не інструкції |

Повідомлення клієнта й документи не змінюють системні правила. Модель не вигадує поля, ціни чи доступність. Підтвердження запису походить від backend після резервування. Без джерела — уточнення або адміністратор.
Memory Bank, кошториси, технічні логи й повна Model Matrix не входять у клієнтський промпт.

## Recent Conversation Context
До 6 релевантних останніх повідомлень у межах токенного бюджету; поточне повідомлення не дублюється в історії.
Стан діалогу, повідомлення й summary — PostgreSQL, ізоляція за client/scenario ID. Підтверджені поля заявки беруться з backend, не з переказу.
Завершення після виконання/передачі або 30 хв неактивності; незавершена заявка зберігається окремо. Повернення починає новий сценарій із потрібним станом. Це не скасовує запис чи окреме 30-хвилинне утримання.

## Conversation Summary
Тригер: історія понад 1000 токенів або запит не вкладається після видалення зайвого. Максимум 300 токенів.
Поля підсумку: потреба, підтверджені побажання, заперечення, невизначеності, відкриті питання, межа охопленої історії.
Не створювати повторно без суттєвих змін. Виклик входить у бюджет; за браком коштів — структурований підсумок кодом. Summary не перезаписує точні бізнес-поля.

## Long-Term Memory
Sheets: клієнти, згоди, каталог, майстри, заявки, записи й статуси. Drive: джерела знань. PostgreSQL: пам’ять розмови, індекс і технічні дані. Calendar: відображення.
Дані отримуються вибірково за ID й правами. Контакти, діалоги, summary, детальний usage — 2 календарні місяці після завершення; активні майбутні записи не видаляються до виконання. Адмін відповідає за актуальність знань.
Видалення поширюється на кеш; правила backup й журналу видалень — [operations.md](operations.md).

## Conversation Indexing
Історія діалогів індексується структурованими ключами client_id, scenario_id, message_id, часом і межею summary; це пропозиція реалізації погодженої ізоляції, не готова схема.
Не шукати персональні діалоги глобально між клієнтами; embeddings історії не створюються.
Індекс знань:
MVP без embeddings і векторної бази.
Тематичний індекс у PostgreSQL. Кнопка «Оновити базу знань»: завантаження Drive → перевірка → активація версії; збій залишає стару версію. Точний український механізм пошуку — за тестами.
Метадані матеріалів: document_id, section_id, topic, service_id, master_id, language, version, status, updated_at, source, text.
Порядок: точні ID/фільтри → категорії, теги й синоніми → текстовий пошук → кілька релевантних фрагментів у бюджеті → уточнення/людина при відсутності джерела.
Розбиття за завершеними темами: послуга, підготовка, правило скасування. Виняток не відривати від правила.
Ціни, тривалість і слоти — зі структурованого джерела. Чернетки й неактивні версії виключені.
Перегляд embeddings: регулярні пропуски пошуку, які не усуваються простими засобами, або суттєве зростання матеріалів.

## Context Retrieval Rules
1. Перевірити особу, операцію та доступ.
2. Отримати стан заявки за ID, актуальні точні дані.
3. Вибрати потрібні останні репліки й summary без дублювання.
4. Для консультації знайти затверджені джерела: ID/категорії/синоніми/текст.
5. Відкинути старі версії й нерелевантне; перевірити бюджет.
6. Без джерела чи при неоднозначності — уточнення/людина.
Чужі дані, всі слоти салону, повна база знань і логи не додаються. Свіжа перевірка часу перед утриманням/підтвердженням обов’язкова.

## Summarization and Context Compression
Тригер summary: історія понад 1000 токенів або повний запит не вкладається у бюджет. Спочатку прибрати зайве. Summary максимум 300 токенів, з межею охопленої історії; без суттєвих нових даних повторно не створювати. За браком бюджету — структурований підсумок полів кодом.
1. Прибрати дублікати й замінені tool results.
2. Прибрати нерелевантні джерела й старі версії.
3. Залишити потрібні останні репліки.
4. Стару частину замінити підсумком.
5. Якщо недостатньо — уточнення або людина.

Зберігати підтверджені поля, ID, заперечення, обмеження клієнта, невизначеності, стан резервування, відкриті питання й причину передачі.
Ціни, час, згоду й критичні правила не переказувати модельним стисканням: подавати структуровано або дослівно.
Підсумок розділяє факти, припущення й питання. Створюється після значущого накопичення; його виклик входить у бюджет.

## Prompt Caching
| Об’єкт | Ключ / механізм | Анулювання |
|---|---|---|
| Правила й схеми | Стабільна версія; provider prompt caching за підтримки | Зміна промпту/схеми |
| Матеріали | ID, версія, мова, тема | Оновлення, деактивація, видалення |
| Пошук | Нормалізований запит, фільтри, версія бази | Зміна матеріалів |
| Каталог | Короткостроково з версією | Зміна послуг, цін, майстрів |
| Підсумок | Клієнт, сценарій, межа охоплених реплік | Суттєві уточнення |

Кеш не підтверджує слот чи бронювання: перед зміною перевірити актуальність. Персональні відповіді не кешувати спільно. FAQ — затверджений текст замість довільної генерації.
TTL: каталог/FAQ 5 хв, пошук 1 хв, показ слотів 15 с. Версія матеріалів/каталогу входить у ключ; зміна анулює старий кеш. Персональний кеш видаляється разом із даними. Provider caching лише після перевірки endpoint/usage; економія не включена до базового кошторису.

## API Parameter Policy
| Параметр / контроль | Політика |
|---|---|
| model | Явний ID матриці; лог фактичної моделі |
| response_format | JSON Schema для наміру, полів, рекомендацій, передачі |
| Підтримка | Endpoint підтримує всі обов’язкові параметри |
| tools | Мінімальні потрібні інструменти й схеми |
| tool_choice | Обмеження сценарієм; без необмежених дій |
| max_tokens / max_completion_tokens | За сумісністю endpoint; спільний бюджет reasoning і видимого output |
| Reasoning | Вимкнений для простих; умовний для складних; S/G — effort |
| temperature | Низька для класифікації/полів за підтримки; значення за тестами |
| Streaming | Можливий для консультації; бізнес-дія після повної валідації |
| Timeout | AI-спроба: коротка 20 с, складна 45 с; Google API 15 с. Загальний AI-deadline 30/60 с з усіма повторами й очікуванням; кожна спроба отримує залишок часу |
| Usage | Кожна спроба; невідоме не означає нуль |

Не надсилати непідтримувані параметри. JSON не доводить істинність. Профілі основних і резервних моделей перевірити перед запуском.

## Rate Limit Strategy
HTTP 429: врахувати Retry-After; без нього дозволений retry через 2–4 с із випадковим розкидом. Якщо очікування не вкладається у deadline/бюджет, не запускати його.
Перед спробою перевіряти глобальний, користувацький і сценарний бюджет. Реалізувати керовану чергу й обмеження паралельності; точні значення квот залежать від endpoint і ще визначаються тестами.
За тривалого обмеження — дозволений fallback або код/адміністратор. Не створювати цикли повторів у SDK, backend і n8n.

## Retry and Backoff
1 retry/операцію, 2/сценарій; 1 fallback/операцію, 2/сценарій; максимум 3 спроби/операцію. Усі входять у ліміти 5/12 та бюджет.
| Ситуація | Дія |
|---|---|
| Rate limit, тимчасовий збій | Retry-After за наявності; без нього дозволена повторна спроба через 2–4 с із випадковим розкидом, лише в бюджеті й deadline |
| Тайм-аут AI | Перевірити доступний статус/usage; врахувати можливу оплату |
| Невалідна схема | Одна спроба виправлення з короткою помилкою |
| Контекст завеликий | Скоротити, не повторювати незмінений запит |
| Немає даних/джерел | Уточнення або людина |
| Модель недоступна | Погоджений fallback у бюджеті |
| Підозрілі факти/заборонена дія | Відхилити; сильніша модель не замінює перевірку |
| Вичерпані ліміти | Код, шаблон, адміністратор |
| Тайм-аут CRM | Звірити запис до повтору бізнес-дії |

Кожна спроба повторно перевіряє бюджет. Backend, n8n і SDK використовують спільний лічильник; вкладені повтори не множать виклики.
Затримка 2–4 с стосується одного дозволеного повтору без Retry-After; нескінченний backoff не застосовується. Загальні deadlines AI 30/60 с включають спроби й очікування.

## Monitoring
Кожна спроба: scenario/operation/request ID, модель/endpoint, input/output/reasoning/cache tokens, фактична вартість або позначена оцінка, latency, retry/fallback причина, помилка, версії промпту/знань, спрацювання ліміту.
Додатково для контексту: токени кожного блоку, кількість джерел, summary/compression events, cache hits/misses, пропуски пошуку. Це технічна деталізація моніторингу; тексти контактів/повні діалоги не потрібні в логах витрат.
Показники: cost per user/scenario, p50/p95, помилки, reasoning calls, retries, fallback. Адмін отримує бюджетні й операційні сповіщення: [Model Strategy](model-strategy.md).
Після простою звірити незавершені операції Sheets/Calendar і звільнити прострочені hold. До початку візиту — одне актуальне повідомлення замість кількох пропущених; після початку нагадування пропустити. Сталий ключ захищає від дубля.
Резерв завершення 20% бюджету; сценарний hard limit має пріоритет над максимумом операції.
50 українських діалогів, ≥95% правильності наміру/полів, усі тестові заперечення збережені; консультації оцінює адмін. Це цілі, не виконані результати. Протокол ще визначити.
Незакрите: [Open Questions](open-questions.md). Тести й реалізація: [Tasks](tasks.md).

## Risks
Переповнення контексту, повторне надсилання історії, дублікати, старі слоти/правила, втрата заперечень у summary, чужі дані, застарілий кеш, надмірні retries і платне reasoning.
Контроль: бюджет до виклику, точний стан окремо, версії, ізоляція, свіжа перевірка, спільні counters, тести. Реєстр R01–R29: [risks.md](risks.md).
Перед пілотом 50 українських діалогів; не менше 95% наміру/полів, збережені всі тестові заперечення. Невизначені API-профілі/механізм пошуку не видавати за реалізовані.
