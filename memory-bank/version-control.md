# Контроль версій — Git

Локальний репозиторій у D:\memory_bank. Публічний віддалений репозиторій: [nazar-yednak/style-salon-mvp](https://github.com/nazar-yednak/style-salon-mvp). Remote origin: https://github.com/nazar-yednak/style-salon-mvp.git. Гілка main відстежує origin/main. Створення й початкове завантаження погоджені користувачем.

## Правила
- Коміт — значущий завершений набір змін із коротким поясненням.
- Перед комітом перевіряти diff, посилання, узгодженість документації, карту й глосарій.
- Не комітити секрети, токени, файл приватних доступів, персональні бізнес-дані, дані контейнерів і backup.
- Для доступів використовувати ігноровану папку access/; для секретів secrets/ або локальний .env. Файл поза цими правилами може потрапити в Git, тому перевірка вмісту обов’язкова.
- .env.example містить лише назви параметрів і порожні/демонстраційні значення.
- Не переписувати історію й не скидати робочі зміни без окремої потреби.

## Архів і копії
Попередній архів документації збережений у початковому стані. Надалі звичайні зміни відстежуються Git; archive/ використовується для завершених етапів, а не копії всіх файлів після кожної правки.
Git не є резервною копією бізнес-даних і не містить секретів. Резервні копії системи ведуться за operations.md.

## Щоденний цикл
Перевірити стан → переглянути зміни → перевірити результат → додати лише потрібні файли → коміт.
Основна гілка main. Автор комітів — наявна Git-конфігурація користувача; її не змінюємо.
