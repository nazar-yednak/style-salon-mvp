| R05 | Доступ до чужих записів чи адмінських команд | Високий | Перевірка особи, ролі та власника на кожній операції |

## Додаткові ризики
| ID | Ризик | Контроль |
|---|---|---|
| R23 | Простій локального комп’ютера | Режим без сну, звірка й відновлення задач після запуску |
| R24 | Summary втрачає заперечення/уточнення | 300 токенів, структуровані поля окремо, тести всіх заперечень |
| R25 | Застарілий кеш або неперевірена версія знань | Версійовані ключі, перевірка до активації, свіжа перевірка слоту |
| R26 | Базовий прогноз понад soft limit | $6.795 проти soft $6, клієнтський hard $8; прогноз, шаблони, вимірювання |
| R27 | Тестовий прайс сприймається як реальний | Явна позначка демонстрації |
| R28 | Втрата ключів backup/n8n | Окремий менеджер паролів, аварійна копія, тест відновлення |
| R29 | Суперечливі версії документації | Карта власників даних, актуальні кореневі документи, архів окремо |
| R30 | Повторна доставка або нова сесія створює зайву AI-оплату чи обходить бюджет | Дедуплікація до AI; спільний user/day/month облік; UE03 |
| R31 | Хибний знаменник юніта або подвійний облік праці/спроб | Перше підтвердження booking_id один раз; історичні скасування не вилучати; окремі компоненти собівартості; UE01 |
| R32 | Середні обсяги приховують піки, імпорт і накопичені фонові задачі | Тести 5/10/20 клієнтів, API-квоти, queue age й відновлення; UE04 |

Уточнення R16/R19/R26: одночасні reasoning, retry й fallback рахувати за унікальними спробами, включно з активними резервами. Нові сесії не скидають користувацькі/періодні бюджети. Запас базової оцінки до клієнтського hard — $1.205; кандидат S-підліміту $1 не покриває весь приклад 10% fallback. Правила й припущення: [Unit Economics and Load Strategy](unit-economics-and-load-strategy.md).

R01 контролюється backend-блокуванням; Sheets не надає транзакційної гарантії всьому циклу. Конкретний механізм ще розробити.
Закриті бізнес-питання не повторюються тут; [відкритий реєстр](open-questions.md). Контроль: [Context Strategy](context-memory-strategy.md), [Model Strategy](model-strategy.md), [Експлуатація](operations.md).
