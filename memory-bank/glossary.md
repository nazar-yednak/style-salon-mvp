# Глосарій
У форматі здачі Context and Memory Strategy — документ context-memory-strategy.md, що об’єднує правила контексту й пам’яті бота.
| Термін | Просте пояснення для «Стиль салон» |
|---|---|
| MVP | Перша робоча версія з погодженими функціями, яку перевіряємо на пілоті |
| Backend | Серверна програма: перевіряє доступ, дані й виконує зміни |
| n8n / workflow | Інструмент і послідовність автоматичних кроків: повідомлення, нагадування, інтеграції |
| API | Правила, за якими програми звертаються одна до одної |
| Endpoint | Конкретна адреса або реалізація API |
| Docker / Docker Compose | Запуск сервісів у контейнерах і керування ними разом |
| PostgreSQL | Технічна база: діалоги, стан, індекс, лічильники й блокування |
| Бізнес-реєстр | Основні дані салону про заявки й записи; у MVP Google Sheets |
| Джерело істини | Місце, за яким визначається остаточний стан даних |
| CRM / Airtable | Система ведення клієнтів/операцій; Airtable заплановано після Sheets |
| LLM / модель | Програма, що розуміє та генерує текст; не гарантує правильність фактів |
| OpenRouter | API-посередник для доступу до погоджених моделей |
| Промпт | Інструкції та дані, передані моделі в одному запиті |
| Контекст | Усе, що модель отримала в поточному виклику |
| Token | Одиниця тексту для обліку обсягу; не дорівнює слову |
| Input / output tokens | Токени запиту / відповіді |
| Context window | Максимальний обсяг, який модель може врахувати в одному виклику |
| Бюджет контексту | Наш практичний ліміт, нижчий за максимум моделі |
| Reasoning / effort | Додаткове міркування моделі та рівень зусиль; може збільшити ціну й час |
| Structured output / JSON Schema | Відповідь за перевірюваною структурою; правильний формат не доводить правдивість |
| Tool calling | Модель пропонує виклик інструмента; backend перевіряє й виконує |
| Short-term memory | Стан і потрібна історія поточного сценарію |
| Long-term memory | Збережені правила, знання й бізнес-дані, які отримуємо вибірково |
| Summary | Короткий підсумок старої розмови; не заміна точних полів |
| Indexing | Організація матеріалів для пошуку за темами, словами й метаданими |
| Embeddings / векторний пошук | Числове представлення змісту для пошуку схожості; у MVP не використовується |
| Cache / TTL | Тимчасово збережений результат / максимальний строк його використання |
| Інвалідація кешу | Припинення використання кешу після зміни джерела |
| Retry | Повтор спроби після дозволеної помилки |
| Fallback | Перехід на резервну модель або сценарій |
| HTTP 429 / Retry-After | Забагато запитів / підказка API, скільки чекати |
| Timeout / deadline | Час окремої спроби / загальний час операції з очікуванням і повторами |
| Usage | Фактичні токени й інші показники виклику |
| Soft / hard limit | Поріг для скорочення витрат / межа припинення нових AI-викликів |
| Polling / webhook | Backend запитує нові повідомлення / Telegram надсилає їх на публічну адресу |
| Hold / утримання | Тимчасова зайнятість слоту на 30 хв до рішення адміна |
| Idempotency / ключ повтору | Захист: повтор тієї самої команди не створює другу операцію |
| Дедуплікація | Видалення або запобігання дублям |
| Блокування | Не дозволяє двом операціям одночасно зайняти один час |
| Синхронізація / звірка | Оновлення Calendar із реєстру / перевірка й виправлення розбіжностей |
| Latency / p95 | Затримка відповіді / межа, в яку вкладаються 95% виміряних випадків |
| Backup / encryption key | Резервна копія / ключ для розшифрування |
| Пілот | Обмежений запуск для перевірки функцій, якості й фактичних витрат |
| Memory Bank | Документація й пам’ять розробки; не контекст клієнтського бота |
| Основне джерело документації | Один актуальний документ, який володіє правилами конкретної теми |
| Покажчик сумісності | Короткий файл за старим шляхом, що веде до актуального документа й архівної версії |
| Маршрут читання | Мінімальний набір документів для конкретного завдання |
| Validation report / звіт перевірки | Що перевірено, які неточності виправлено й що ще не підтверджено реалізацією |
| Inference-тест | Реальний API-виклик моделі на тестових даних; відрізняється від читання каталогу |
| finish_reason | Причина завершення відповіді; обрив за лімітом потребує перевірки результату |
| Ретроспектива | Аналіз завершеного етапу: що спрацювало й що покращити |
| Git / репозиторій | Система історії змін / папка з файлами та їх версіями |
| Commit / коміт | Зафіксований набір змін із поясненням |
| Branch / гілка | Окрема лінія роботи; основна гілка цього проєкту main |
| Diff | Порівняння: які рядки додані, змінені або видалені |
| .gitignore | Правила виключення локальних файлів із відстеження; не замінює перевірку секретів |
| Remote / віддалений репозиторій | Копія Git на сервері; у проєкті origin веде до публічного GitHub style-salon-mvp |
