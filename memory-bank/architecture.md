# Архітектура — Стиль салон, MVP 1
Статус: погоджені компоненти й відповідальність, реалізація не виконана.

| Компонент | Відповідальність |
|---|---|
| Два Telegram-боти | Клієнтський діалог; адміністративні кнопки й форми |
| TypeScript/Node.js backend | Доступ, валідація, зміни записів, блокування, повтори, маршрутизація AI, бюджет |
| Google Sheets | Остаточний бізнес-реєстр: клієнти, згоди, послуги, заявки, записи, статуси |
| Google Calendar | Календар майстра; відображення підтверджених записів і утримань |
| PostgreSQL | Пам’ять розмови, summary, технічні лічильники, блокування, usage, тематичний індекс; технічна БД n8n |
| n8n | Сценарії, фонові дії, повідомлення, нагадування; бізнес-команди через backend |
| Google Drive | Джерела бази знань; перевірена версія активується адміністратором |
| OpenRouter / AI | Консультація, розбір тексту, підбір; не авторитет для цін, прав чи резервування |

Docker Compose на комп’ютері власника, Docker встановлений. Long polling через backend рекомендований; ще не затверджений. Для стандартного n8n Telegram Trigger потрібен webhook.
MVP без embeddings; сховище PostgreSQL не стає джерелом істини бізнес-записів. Airtable — майбутня заміна Sheets.

## Узгодженість
Усі зміни через backend. Перевірку й створення утримання серіалізувати для майстра; конкретний механізм/схему ще спроєктувати. Однієї перевірки Calendar чи атомарного Sheets-запиту недостатньо для захисту цілого циклу.
Зберігати внутрішній ID, Calendar event ID, ключ операції, версію та статус синхронізації. Тайм-аут → звірка до повтору. При перенесенні зберігати старий запис до успіху.
Прямі правки Calendar/Sheets поза ботом обмежені; процедуру виявлення розбіжностей потрібно реалізувати.
Резервування AI-бюджету враховує паралельні виклики. SDK/backend/n8n мають спільний облік спроб.
